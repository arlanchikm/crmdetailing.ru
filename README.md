# CRM Detailing

Мультитенантная CRM для детейлинг-центров и автомоек. Сервис объединяет расписание работ, клиентскую базу, команду, каталог услуг, склад, платежи и аналитику в одном рабочем пространстве компании.
Файл crmdetailing.pdf - презентация для ознакомления с основными возможностями и визуалом.

## Возможности

### Компании и доступ

- Регистрация компании с созданием владельца, базовой роли и справочников.
- Изоляция данных по компаниям (tenant): запросы, сотрудники и рабочие данные связываются с компанией и проверяют членство пользователя.
- Работа компании на поддомене вида `slug.crmdetailing.ru`; в локальном режиме доступны `slug.localhost` и специальный вход `/local/<slug>/`.
- Роли и разрешения, рабочие локации и распределение доступа сотрудников по локациям.
- Отдельные экраны платформенного оператора, онлайн-записи и базы поддержки на зарезервированных поддоменах.

### Записи и клиенты

- Календарь записей с режимами отображения по сотрудникам и рабочим постам.
- Создание, редактирование, перенос, архивирование и удаление записей; назначение услуг, исполнителей и поста.
- График смен сотрудников, рабочие часы компании, занятость команды и расчёт доступного времени для онлайн-записи.
- Карточки клиентов и автомобилей, история визитов и оплат, классы автомобилей и карта повреждений.
- Публичная ссылка для оценки клиента и ведение претензий с причинами, решениями и финансовыми последствиями.

### Услуги, команда и материалы

- Категории услуг, длительность, цены и разные цены по классу автомобиля.
- Сотрудники, роли, услуги, смены и настройки оплаты труда.
- Склад расходных материалов: категории, нормы списания по услугам, поступления, списания, инвентаризации и история движений.
- Уведомления о критических остатках и других операционных событиях.

### Финансы и аналитика

- Оплаты наличными, картой, переводом и QR; частичные оплаты, возвраты и скидки с ограничениями ролей.
- Кассовые смены и контроль денежных расхождений.
- Учёт расходов, расчёт зарплаты и аналитика выручки, услуг, сотрудников, загрузки, материалов, повторных визитов, оценок и претензий.
- Тарифы, пробный период, промокоды и подписки. Интеграция с ЮKassa обрабатывает результат оплаты через webhook; в новом окружении платёжные ключи нужно задать отдельно.

### Онлайн-запись, уведомления и безопасность

- Публичная форма записи, ссылка и `iframe` для сайта компании; форма показывает доступное время и создаёт запись в CRM.
- Настройка внешнего вида формы записи и фонового изображения.
- Уведомления в интерфейсе и Web Push; фоновый Celery worker обрабатывает периодические задачи.
- Смена и сброс пароля, подтверждение email, email-двухфакторная аутентификация и резервные коды.
- Импорт клиентов, автомобилей, сотрудников, расходников и остатков из CSV/XLSX/XLS с предварительным просмотром и отчётом.
- Документы, согласия и фиксация принятых версий юридических документов. Для публикации заполните заменённые в копии реквизиты.

### Каналы и интеграционные заделы

Для входящих обращений предусмотрена общая модель интеграционных каналов и заявок. Реализована обработка заявок с сайта. Структура допускает подключение Avito и телефонии, но автоматическая работа с чатами Avito и ИИ-агент в этом снимке исходников не реализованы.

## Технологии и устройство

- Python 3.12 и Django 5.2.
- PostgreSQL 17 — постоянные данные CRM.
- Redis 7 — брокер фоновых задач и кэш/очереди.
- Celery — фоновые и периодические задачи.
- Docker Compose — локальные и production-сервисы.
- Gunicorn — production WSGI-сервер; Caddy — HTTPS и reverse proxy.
- Django templates, CSS и JavaScript — веб-интерфейс; миграции Django описывают изменения схемы.

Основной код расположен в `apps/`: `accounts`, `tenants`, `customers`, `operations`, `catalog`, `staff`, `inventory`, `analytics`, `payroll` и `core`. Конфигурация Django — в `config/`, интерфейс — в `templates/` и `static/`, развертывание и резервное копирование — в `deploy/` и `bin/`.

Мультитенантный middleware определяет компанию по поддомену и привязывает её к запросу. В локальном режиме разрешён `localhost`, где `/local/<slug>/` выбирает компанию через сессию. Production-конфигурация использует отдельную внутреннюю Docker-сеть: наружу публикуются только HTTP/HTTPS порты Caddy, а PostgreSQL и Redis остаются внутри сети.

## Локальный запуск

### Требования

- Git.
- Docker Engine с Docker Compose v2 или Docker Desktop.
- Свободный порт `8000`.

Отдельно устанавливать Python, PostgreSQL и Redis для приложения не требуется: локальный Compose запускает их контейнерами.

### 1. Получите исходники и создайте локальные настройки

```bash
git clone https://github.com/arlanchikm/crmdetailing.ru.git
cd crmdetailing.ru
cp .env.example .env
```

Откройте `.env` и измените как минимум `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD`. Используйте только локальные тестовые значения; не копируйте production-секреты в Git. Файл `.env` исключён из Git правилами `.gitignore`.

### 2. Запустите приложение

```bash
./bin/dev up --build -d
```

Дождитесь, пока PostgreSQL и Redis станут доступны, затем примените миграции:

```bash
./bin/dev exec web python manage.py migrate
```

### 3. Создайте тестовую компанию и владельца

```bash
./bin/dev exec web python manage.py bootstrap_tenant \
  --name "Демо-студия" \
  --slug demo \
  --owner-email owner@example.test
```

Команда попросит ввести пароль владельца интерактивно. Задайте пароль длиной не менее 10 символов. Не передавайте пароль в аргументах команды.

### 4. Войдите в CRM

Откройте <http://localhost:8000/local/demo/>. Адрес установит локальный контекст компании и перенаправит на форму входа. Используйте email владельца и пароль, заданные выше.

Полезные адреса:

- Главная страница: <http://localhost:8000/>
- Вход в рабочее пространство: <http://localhost:8000/local/demo/>
- Проверка здоровья приложения: <http://localhost:8000/health/>
- Альтернативный адрес компании: <http://demo.localhost:8000/> (если браузер и система разрешают wildcard-поддомены `.localhost`).

### Полезные команды

```bash
# Просмотреть запущенные сервисы
./bin/dev ps

# Посмотреть логи приложения
./bin/dev logs -f web

# Запустить тесты Django
./bin/dev exec web python manage.py test

# Остановить сервисы, сохранив локальные данные в Docker volumes
./bin/dev down
```

`./bin/dev down` оставляет данные PostgreSQL и Redis в volumes. Команда `./bin/dev down -v` удаляет volumes и безвозвратно очищает локальную базу — используйте её только если действительно хотите начать заново.

## Переменные окружения

- `.env.example` — настройки локальной среды.
- `.env.production.example` — пример для отдельного production-развертывания.
- `DJANGO_PLATFORM_OWNER_EMAIL` задаёт email оператора платформы; установите адрес существующего оператора до применения соответствующей миграции.
- Реальные файлы `.env`, `.env.production`, SMTP и YooKassa-ключи должны храниться вне Git и иметь ограниченные права доступа.

Для локального запуска email, онлайн-платежи и production HTTPS не обязательны. SMTP и ЮKassa настраиваются отдельно, когда нужно проверять соответствующие сценарии. Production Compose и Caddy описаны в `compose.prod.yaml` и `deploy/Caddyfile`; перенос на новый сервер — в [`PROMPT_DEPLOY_ON_NEW_SERVER.md`](PROMPT_DEPLOY_ON_NEW_SERVER.md).
